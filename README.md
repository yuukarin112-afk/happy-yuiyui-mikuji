# はっぴーゆいゆいみくじ

## 1. サービス概要
- このサービスはどんなサービスか
  今日の運勢・小倉唯さんのおすすめ楽曲・今日のはっぴーおまじないをランダムで提案し、日常のちょっとした幸せに気づくきっかけをつくるかわいいWebアプリです。
- 誰の、どんな課題を、どう解決するか
  占いや小倉唯さんが好きで、SNSなどで他人の幸せと比べてしまいがちな人が、曲選びの迷いを減らしつつ、身近な小さな幸せに目を向けて前向きな一日を送れるようにします。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情
- いつ・どんな状況で・どんな気持ちになったか
  普段から占いが好きで、日々の生活の中で小倉唯さんの楽曲1曲分の筋トレを続けています。その中で、毎回どの曲にするか選ぶ手間があったり、ついお気に入りの曲ばかり聴いてしまったりする感覚がありました。また、SNSを見ていると他人の華やかな部分や幸せそうな投稿が目に入り、無意識に自分と比べて落ち込んだり、身近にある小さな幸せを見落としてしまったりすることがありました。

### 2-2. なぜそれが「気になった」のか
- 占いの結果によって一日の意識や行動が変わる面白さを普段から楽しんでいるため、「今日の気分や行動を後押ししてくれる仕組み」があると毎日がもっと楽しくなると感じたからです。
- また、SNSで人と比べてしまいがちな自分自身に対して、「特別な出来事だけでなく、日常のちょっとした幸せにも目を向けられたら心が軽くなるはず」という価値観を大切にしているため、強く気になりました。

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと
- 毎日の筋トレや気分転換で聴く曲を毎回選ぶのが少し面倒で、聴く曲が偏りがちになる。
- SNSなどを見て他人と比べることで、自分の日常にある小さな幸せに気づきにくくなる。

### 3-2. 本当に解決したい課題は何か
- なぜ曲を選ぶのが面倒・偏るのか？
  → 毎回「どれにしようか」と決断する小さな負担があり、慣れた選択肢に頼ってしまうから。
- なぜSNSを見ると比べてしまったり、幸せを見落としたりするのか？
  → 他人の切り取られた良い部分ばかりに触れることで、自分の日常の小さな良い出来事や感情に意識が向かなくなるから。
- なぜそれが困るのか？
  → 気持ちの切り替えや楽しみが減り、自分自身の日常を肯定しにくくなってしまうから。

→ 本当に解決したい課題
日々の選択のちょっとした負担や、他人の幸せと比べてしまう流れの中で、「自分の身近にある小さな幸せに気づき、前向きに一日を過ごすきっかけ」をつくりにくくなっていること。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー
- 年齢設定： 20代〜30代前半（想定ペルソナ：推しの活動や日常の息抜きを大切にしている女性）
  - 理由： 仕事や日々の生活の中でルーティンや気分転換を求めやすく、SNSに触れる機会も多い年代のため、短時間で心がほっとする体験や行動のきっかけが活きやすいと考えたため。
- 生活・状況設定： 普段から占いや小倉唯さんの楽曲が好きで、毎日のちょっとした習慣（筋トレや気分転換など）を大切にしている。SNSを見ることもあり、ふと他人と比べてしまうことがある。
  - 理由： 占いの結果で一日の意識が変わる楽しさや、曲選びの決断が減るラクさ、そして日常の小さな幸せに気づくメッセージが、そのまま生活の中の助けになるため。
- 環境設定： スマートフォンやPCからブラウザで気軽にアクセスできる環境（自宅でのリラックスタイムや、出かける前・筋トレ前など）。
  - 理由： 思い立ったときにすぐ開いて、占い・楽曲・おまじないをサクッと受け取れる手軽さが重要になるため。

### 4-2. 自分とユーザーの距離
- 自分自身
  - 理由： 「占いが好きで結果によって一日の行動が変わるのが楽しい」「小倉唯さんの曲で筋トレや気分転換をする際に決断を減らしつつ色々な曲を楽しみたい」「日常のちょっとした幸せに気づきたい」という動機が、すべて自分自身の体験や想いから出発しているため。

### 4-3. 実際に使われる可能性について（需要・存在確認）
- まず最初に使ってくれそうな人：自分自身や、小倉唯さんの楽曲・かわいい世界観・占いが好きな人。
- どんな場面でこのアプリを思い出すか：朝起きて一日のスタートを切るとき、筋トレやストレッチを始める前、SNSを見て少し気持ちが疲れたとき・気分を変えたいとき。
- 今の生活の中で、代わりに使っているものは何か：占いサイトやアプリ、音楽アプリのプレイリスト・検索、SNSなど。
- それを置き換えてまで使う理由はあるか：「今日の運勢」「小倉唯さんのおすすめ楽曲」「はっぴーおまじない」が1回でまとめてランダム表示され、曲選びの手間を減らしつつ身近な幸せに気づく体験まで一貫して得られる点は、既存ツールとは異なる楽しさがあるため。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ（導入・継続の流れ）
- 知る・思い出すきっかけ：気分転換したいときや、今日の運勢・おすすめの曲を知りたいとき、日常のちょっとした幸せを感じたいとき。
- 最初の一歩：最初はシンプルな新規登録・ログインを行い、マイページや専用画面のボタンを押すだけですぐに結果がわかる手軽な導線にする。
- 利用を続ける理由：ランダム性によって毎回違う楽曲やおまじないに出会える楽しさがあり、占いの結果やメッセージが日々の行動や気持ちの切り替えにつながるため。

## 7. このアプリで実現すること

### MVPで作る機能
- トップ画面（かわいい世界観のデザイン）
- ログイン画面（ユーザーごとの日課や結果の管理・マイページ利用のための認証機能）
- 1日1回限定のランダム表示機能（占いの性質を活かし、引き直しは不可とする。運勢は「大吉・吉・中吉・小吉」のみを用意し、結果で落胆しない設計にする）
  - 今日の運勢
  - 今日のおすすめ楽曲（小倉唯さんの楽曲）
  - 今日のはっぴーおまじない（最大30種類からランダム表示）
- マイページ画面（ログイン後のユーザー向け画面）

### 本リリースで作る機能
- マイページでの記録・参照機能（過去に引いた運勢・おすすめ楽曲・はっぴーおまじないの履歴一覧や振り返り）
- おすすめ楽曲からのYouTube Musicリンクボタン（結果画面や履歴からすぐに楽曲を聴きに行ける導線）
- 楽曲のお気に入りボタン機能（ランダムで出会った楽曲や好きな曲を保存・管理できる機能）
- UI・アニメーションのさらなるブラッシュアップ（かわいい演出の強化など）

## 8. このアプリの懸念点とその対策

### 懸念点
- 何が問題になりそうか：ランダム表示のバリエーションが少ないと、数回使っただけで同じ組み合わせばかり出て飽きてしまったり、「はっぴーおまじない」が押し付けがましく感じられたりする可能性がある。
- なぜそう思うか：毎日使う・繰り返し楽しむアプリを目指す場合、新鮮さや心地よい距離感が欠けると継続につながりにくいため。
- そのために考えている対策：運勢・楽曲・はっぴーおまじないのデータをあらかじめ複数用意して組み合わせの幅を持たせ、おまじないの文面も「〜してみよう！」と押し付けるのではなく、日常の小さな幸せに気づく優しいトーンに整える。

---

## 9. 今後の展開・発展の方向性
- 機能追加の方向性：マイページに蓄積された「引いた曲やおまじない・運勢の履歴」の参照機能に加え、楽曲のお気に入りボタンやYouTube Musicへのリンクボタンを実装することで、ランダムで出会った楽曲をそのまま聴いたり、自分だけのお気に入りリストとして振り返ったりできるようにする。
- UI・体験の改善：1日1回しか引けない特別感や、お気に入り登録・YouTube Musicへのスムーズな導線を活かし、かわいい配色やカード演出、押したときのワクワク感を高めるアニメーションを工夫する。
- 機能以外の工夫：運勢を「大吉・吉・中吉・小吉」のみに絞る工夫や、最大30種類の優しいおまじない文面を通じて、占いの結果で落ち込むのではなく日常の小さな幸せに目を向けられる体験を大切にする。自分自身の毎日の筋トレや気分転換の中でも実際に使い続け、使い心地を確かめながら改善を重ねていく。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術
- フレームワーク：Ruby on Rails
- DB：PostgreSQL
- デプロイ先：Render（検討中）
- 使用予定ライブラリ：未定（必要に応じて選定）

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Ruby on Rails | 採用 | カリキュラムで学んだ知識を活かし、認証機能やデータ管理を含むWebアプリを着実に形にできるため |
| Docker（Ubuntu / VS Code） | 採用 | 開発環境を統一でき、カリキュラムと同じ手順でスムーズに開発・環境構築を進められるため |
| React / Next.js | 不採用 | 学習コストが高くキャッチアップに時間がかかるため、まずはRailsのみでMVPを完成させることを優先したため |

- 今回チャレンジしたい点：自分の企画・世界観をゼロから設計し、かわいいデザインや1日1回のランダム表示・マイページ機能などの体験を形にすること。
- 不安な点：1日1回制限のデータ設計や画面デザインの調整、要件を詰め込みすぎてMVPの完成が遅れること。

### 10-3. キャッチアップ不足の懸念
- まずはRuby on Railsの基本構成でMVPを確実に完成させることを優先し、追加で導入したい技術や装飾・機能は、基本機能が動いてから段階的に調査・検証しながら組み込むようにする。
