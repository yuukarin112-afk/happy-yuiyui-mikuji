# はっぴーゆいゆいみくじ

## 1. サービス概要
- このサービスはどんなサービスか
  今日の運勢・小倉唯さんのおすすめ楽曲・今日のはっぴーおまじないを1日1回ランダムで提案し、日常のちょっとした幸せに気づくきっかけをつくるかわいいWebアプリです。
- 誰の、どんな課題を、どう解決するか
  占いや小倉唯さんが好きで、SNSなどで他人の幸せと比べてしまいがちな人が、曲選びの迷いを減らしつつ、身近な小さな幸せに目を向けて前向きな一日を送れるようにします。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情
- いつ・どんな状況で・どんな気持ちになったか
  普段から占いが好きで、日々の生活の中で小倉唯さんの楽曲1曲分の筋トレを続けています。その中で、毎回どの曲にするか選ぶ手間があったり、ついお気に入りの曲ばかり聴いてしまったりする感覚がありました。また、SNSを見ていると他人の華やかな部分や幸せそうな投稿が目に入り、無意識に自分と比べて落ち込んだり、身近にある小さな幸せを見落としてしまったりすることがありました。

### 2-2. なぜそれが「気になった」のか
- 占いの結果によって一日の意識や行動が変わる面白さを普段から楽しんでいるため、「今日の気分や行動を後押ししてくれる仕組み」があると毎日がもっと楽しくなると感じたからです。
- また、SNSで人と比べてしまいがちな自分自身に対して、「特別な出来事だけでなく、日常のちょっとした幸せにも目を向けられたら心が軽くなるはず」という価値観を大切にしているため、強く気になりました。

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと
- 毎日の筋トレや気分転換で聴く曲を毎回選ぶのが少し面倒で、聴く曲が偏りがちになる。
- SNSなどを見て他人と比べることで、自分の日常にある小さな幸せに気づきにくくなる。

### 3-2. 本当に解決したい課題は何か
- なぜ曲を選ぶのが面倒・偏るのか？
  → 毎回「どれにしようか」と決断する小さな負担があり、慣れた選択肢に頼ってしまうから。
- なぜSNSを見ると比べてしまったり、幸せを見落としたりするのか？
  → 他人の切り取られた良い部分ばかりに触れることで、自分の日常の小さな良い出来事や感情に意識が向かなくなるから。
- なぜそれが困るのか？
  → 気持ちの切り替えや楽しみが減り、自分自身の日常を肯定しにくくなってしまうから。

→ 本当に解決したい課題
日々の選択のちょっとした負担や、他人の幸せと比べてしまう流れの中で、「自分の身近にある小さな幸せに気づき、前向きに一日を過ごすきっかけ」をつくりにくくなっていること。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー
- 年齢設定： 20代〜30代前半（想定ペルソナ：推しの活動や日常の息抜きを大切にしている女性）
  - 理由： 仕事や日々の生活の中でルーティンや気分転換を求めやすく、SNSに触れる機会も多い年代のため、短時間で心がほっとする体験や行動のきっかけが活きやすいと考えたため。
- 生活・状況設定： 普段から占いや小倉唯さんの楽曲が好きで、毎日のちょっとした習慣（筋トレや気分転換など）を大切にしている。SNSを見ることもあり、ふと他人と比べてしまうことがある。
  - 理由： 占いの結果で一日の意識が変わる楽しさや、曲選びの決断が減るラクさ、そして日常の小さな幸せに気づくメッセージが、そのまま生活の中の助けになるため。
- 環境設定： スマートフォンやPCからブラウザで気軽にアクセスできる環境（自宅でのリラックスタイムや、出かける前・筋トレ前など）。
  - 理由： 思い立ったときにすぐ開いて、占い・楽曲・おまじないをサクッと受け取れる手軽さが重要になるため。

### 4-2. 自分とユーザーの距離
- 自分自身
  - 理由： 「占いが好きで結果によって一日の行動が変わるのが楽しい」「小倉唯さんの曲で筋トレや気分転換をする際に決断を減らしつつ色々な曲を楽しみたい」「日常のちょっとした幸せに気づきたい」という動機が、すべて自分自身の体験や想いから出発しているため。

### 4-3. 実際に使われる可能性について（需要・存在確認）
- まず最初に使ってくれそうな人：自分自身や、小倉唯さんの楽曲・かわいい世界観・占いが好きな人。
- どんな場面でこのアプリを思い出すか：朝起きて一日のスタートを切るとき、筋トレやストレッチを始める前、SNSを見て少し気持ちが疲れたとき・気分を変えたいとき。
- 今の生活の中で、代わりに使っているものは何か：YouTube Music（シャッフル再生・プレイリスト）、一般的な占いアプリ・Webサイト、SNSなど。
- それを置き換えてまで使う理由はあるか：「今日の運勢」「小倉唯さんのおすすめ楽曲」「はっぴーおまじない」が1回でまとめてランダム表示され、曲選びの手間を減らしつつ身近な幸せに気づく体験まで一貫して得られる点は、既存ツールとは異なる楽しさがあるため。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ（導入・継続の流れ）
- 知る・思い出すきっかけ：気分転換したいときや、今日の運勢・おすすめの曲を知りたいとき、日常のちょっとした幸せを感じたいとき。
- 最初の一歩：シンプルな新規登録・ログインを行い、ボタンを押すだけですぐに今日の結果がわかる手軽な導線にする。
- 利用を続ける理由：1日1回の特別感とランダム性によって毎回違う楽曲やおまじないに出会える楽しさがあり、マイページでの振り返りや統計・お気に入り機能によって日々の習慣や気持ちの切り替えにつながるため。

## 5. 既存サービス・競合調査

### 5-1. 似たサービス・代替手段の調査
- サービス名①：YouTube Music
  - URL：https://music.youtube.com/
  - どんなことができるか：小倉唯さんの楽曲をストリーミング再生したり、プレイリスト作成やシャッフル再生で楽曲を聴いたりできる。
- サービス名②：Yahoo!占い（一般的な占いWebサイト・アプリ）
  - URL：https://fortune.yahoo.co.jp/
  - どんなことができるか：毎日無料で今日の運勢やラッキーアイテム・ラッキーアクションなどを占うことができる。

### 5-2. それでも自分が作りたい理由
- YouTube Musicの場合、自分で曲を選んだりプレイリストを作ったりする必要があり、日々の筋トレや気分転換のたびに「どの曲にしようか」と決断する小さな手間が発生したり、ついお気に入りの曲ばかり聴いてしまったりする。また、占い機能はないため「今日の運勢とセットで1曲だけ提案してもらう」体験はできない。
- 一般的な占いサイトの場合、情報量が多すぎたり、「凶」などの悪い結果を見て逆に気分が落ち込んでしまったりすることがある。また、小倉唯さんの楽曲と結びついたワクワク感がない。

### 5-3. 差別化を「体験価値」で表現する
- 私のアプリの差別化ポイント：
  「小倉唯さんが好きで、日々の筋トレや気分転換の曲選びに迷いがちな人」が、「1日1回のボタンを押すだけで、落ち込まない優しい運勢・推し曲1曲・日常の小さな幸せに気づくおまじないをまとめて受け取り、決断の手間を減らしながら前向きな気持ちでYouTube Musicへ移動できる体験」ができる点。

- 気持ちの変化：占いやかわいい世界観、楽曲に触れることで気分が明るくなり、ほっと心が和らぐ。
- 考え方の変化：SNSなどで他人と比べるのではなく、「自分の身近にも小さな幸せがある」と気づけるようになる。

### 6-2. 価値を一文で表す
- 「このサービスは占いや小倉唯さんの楽曲が好きで、日々のちょっとした幸せを見落としがちな人が、ランダムな提案をきっかけに気分を切り替え、身近な幸せに気づいて前向きに過ごせるようになるサービス」

## 7. このアプリで実現すること

### MVPで作る機能（5機能）
1. ユーザー新規登録機能
2. ログイン・ログアウト機能
3. ユーザー情報編集機能（ニックネームやメールアドレス等の編集）
4. 1日1回限定のランダム抽選・結果表示機能（毎日日本時間7:00にリセット。占いの性質を活かし引き直しは不可とする。運勢は「大吉・吉・中吉・小吉」のみを用意し、結果で落胆しない設計にする）
   - 今日の運勢
   - 今日のおすすめ楽曲（小倉唯さんの楽曲：MVP時点では最新アルバムの12曲を用意）
   - 今日のはっぴーおまじない（最大30種類からランダム表示）
5. マイページ表示機能（ログイン中のユーザー情報および、本日引いた抽選結果の再確認）

### 本リリースで作る機能（6機能）
6. 過去の抽選履歴一覧表示機能（マイページ内で過去に引いた運勢・おすすめ楽曲・はっぴーおまじないを振り返る機能）
7. おすすめ楽曲からのYouTube Musicリンク遷移機能（結果画面や履歴から公式YouTube Musicへすぐに聴きに行ける導線）
8. 楽曲のお気に入り登録・解除・一覧表示機能（ランダムで出会った楽曲や好きな曲を保存・管理できる機能）
9. 楽曲一覧・検索機能（登録されている楽曲の一覧表示および曲名・キーワード等での検索）
10. 統計・振り返り機能（マイページ内でこれまでの抽選回数や運勢の割合、よくおすすめされた楽曲などを確認できる機能）
11. 管理画面機能（管理者が楽曲データ・はっぴーおまじないデータの登録・編集・削除を行える機能）

### データの用意方法と権利面への配慮
- データの用意方法：YouTube Musicの公式APIは一般公開されていないため、MVP時点では `db/seeds.rb` を用いて運勢（4種類）・楽曲（最新アルバム曲12曲）・はっぴーおまじない（最大30種類）のデータを登録する。本リリースでは管理画面から楽曲やおまじないの追加・編集ができるようにし、楽曲数も順次拡充していく予定。
- 権利面への配慮：実在のアーティストを扱うため、ジャケット画像・歌詞・アーティスト本人の画像や音源データは一切使用せず、曲名テキストと公式YouTube Musicへの外部リンク掲載のみにとどめる。

## 8. このアプリの懸念点とその対策

### 懸念点
- 何が問題になりそうか：ランダム表示のバリエーションが少ないと、数回使っただけで同じ組み合わせばかり出て飽きてしまったり、「はっぴーおまじない」が押し付けがましく感じられたりする可能性がある。また、実在アーティストの楽曲を扱うため著作権・肖像権などの権利侵害にならないよう注意が必要。
- なぜそう思うか：毎日使う・繰り返し楽しむアプリを目指す場合、新鮮さや心地よい距離感が欠けると継続につながりにくいため。また、外部リンクや楽曲情報の取り扱いルールを明確にしておく必要があるため。
- そのために考えている対策：運勢（4種）・楽曲（MVP時は12曲、以降拡充）・はっぴーおまじない（最大30種）を組み合わせて毎日異なる結果を楽しめるようにし、おまじないの文面も日常の小さな幸せに気づく優しいトーンに整える。さらに、ジャケット画像や歌詞は掲載せず曲名と公式YouTube Musicリンクのみを扱うことで権利面を遵守する。

## 9. 今後の展開・発展の方向性
- 機能追加の方向性：マイページに蓄積された「引いた曲やおまじない・運勢の履歴」の参照機能に加え、統計・振り返り機能や楽曲のお気に入りボタン・YouTube Musicへのリンクボタン、楽曲検索機能を実装することで、ランダムで出会った楽曲をそのまま聴いたり、自分だけのお気に入りリストとして振り返ったりできるようにする。
- UI・体験の改善：1日1回しか引けない特別感や、お気に入り登録・YouTube Musicへのスムーズな導線を活かし、かわいい配色やカード演出、押したときのワクワク感を高めるアニメーションを工夫する。
- 機能以外の工夫：運勢を「大吉・吉・中吉・小吉」のみに絞る工夫や、最大30種類の優しいおまじない文面を通じて、占いの結果で落ち込むのではなく日常の小さな幸せに目を向けられる体験を大切にする。自分自身の毎日の筋トレや気分転換の中でも実際に使い続け、使い心地を確かめながら改善を重ねていく。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術
- フレームワーク：Ruby on Rails
- DB：PostgreSQL
- デプロイ先：Render（検討中）
- 使用予定ライブラリ：devise（ユーザー認証機能）

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Ruby on Rails | 採用 | カリキュラムで学んだ知識を活かし、認証機能やデータ管理を含むWebアプリを着実に形にできるため |
| Docker（Ubuntu / VS Code） | 採用 | 開発環境を統一でき、カリキュラムと同じ手順でスムーズに開発・環境構築を進められるため |
| devise | 採用 | Railsにおける認証機能の定番ライブラリであり、ドキュメントが豊富で安全かつスムーズにログイン・新規登録・ユーザー編集機能を実装できるため |
| React / Next.js | 不採用 | 学習コストが高くキャッチアップに時間がかかるため、まずはRailsのみでMVPを完成させることを優先したため |

- 今回チャレンジしたい点：自分の企画・世界観をゼロから設計し、かわいいデザインや1日1回（朝7時切り替え）のランダム表示・マイページ機能・統計振り返り機能などの体験を形にすること。
- 不安な点：朝7時切り替えによる1日1回制限の判定ロジックや、要件を詰め込みすぎてMVPの完成が遅れること。
- 1日1回制限の判定方法（設計方針）：Railsのタイムゾーンを日本時間（`Tokyo`）に設定し、現在の日本時間が7:00以降であれば「当日7:00〜翌日6:59」、7:00未満であれば「前日7:00〜当日6:59」を1日の判定期間とする。抽選履歴テーブルに保存されたユーザーの抽選日時（`created_at`）がこの期間内に存在するかどうかで、当日すでに抽選済みかを判定する。

### 10-3. キャッチアップ不足の懸念
- まずはRuby on Railsとdeviseの基本構成でMVPを確実に完成させることを優先し、本リリースで追加する機能（統計表示や検索など）はMVP完成後に段階的に調査・検証しながら組み込むようにする。
